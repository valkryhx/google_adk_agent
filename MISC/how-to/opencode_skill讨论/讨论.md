1. 解决并发污染：使用闭环作用域 (Closure Pattern)
在你的 file_editor 中，_editor 是一个全局实例。这对于纯粹的文件读写没有问题，但 OpenCode 涉及到长链接的 SSE 流式响应和独立任务的会话状态（Session）。
如果 Ciri 同时处理多个用户的请求，全局实例会导致 status_reporter 被互相覆盖，前端会收到串线的日志。

优化方案： 利用 Python 的闭包特性，在 get_tools 内部动态生成 Tool 函数。这样每次 Ciri 针对新会话加载 Skill 时，都会创建一个完全独立的 status_reporter 绑定，彻底杜绝多租户并发状态污染。

2. 精确的 Prompt 边界：Docstring 路由优化
Ciri 的主模型需要非常清晰地知道：什么时候该自己用 file_editor 改文件，什么时候该把整包任务丢给 OpenCode？

优化方案： 在 OpenCode 工具的 Docstring 中加入明确的“降级/委派（Delegation）”暗示，引导 Ciri 把高复杂度的工程任务外包出去，而不是自己一行一行去写。

3. 标准化的代码实现 (skills/opencode/tools.py)
这是完全贴合你 Ciri SKILL.md 规范的终极版本代码，它既保持了轻量级，又无缝对接了你主进程里的 status_reporter 机制：

Python
import asyncio
from typing import List
from opencode_ai import Opencode

# OpenCode 服务的本地地址
OPENCODE_BASE_URL = "http://127.0.0.1:4096"

def get_tools(*args, **kwargs) -> List:
    """
    动态加载 OpenCode 技能。
    利用 kwargs 捕获从 main_web_start_steering 注入的并发安全上下文。
    """
    status_reporter = kwargs.get('status_reporter')
    interruption_queue = kwargs.get('interruption_queue')

    async def opencode_delegate(prompt: str) -> str:
        """
        [Autonomous Sub-Agent] 专门处理复杂编码、多文件重构、环境配置和终端命令的底层智能体。
        
        使用场景：
        1. 当你需要执行需要反复试错的复杂代码任务（如安装依赖并修复报错）时。
        2. 当任务跨越多个文件，且你需要一个能自主运行 bash 命令并测试结果的助手时。
        
        注意：
        请在 prompt 中极其详尽地描述任务背景、目标路径和具体要求。不要将此工具用于简单的单文件查看（请优先使用 file_editor）。
        
        Args:
            prompt: 给 OpenCode 智能体的详细任务指令集。
        """
        # 1. 中断防御检查
        if interruption_queue and not interruption_queue.empty():
            return "任务尚未开始即被用户中断。"

        try:
            client = Opencode(base_url=OPENCODE_BASE_URL)
            # 为当前任务创建一个隔离的沙盒 Session
            session = client.session.create()
        except Exception as e:
            return f"❌ 无法连接到 OpenCode 服务，请检查端口 {OPENCODE_BASE_URL} 是否存活。错误: {e}"

        if status_reporter:
            status_reporter("opencode_start", {"message": "正在唤醒 OpenCode 底层代码智能体..."})

        # 用于喂给 Ciri 主模型的“干净上下文”
        execution_trace = f"【OpenCode 运行轨迹 (Session: {session.id})】\n"

        try:
            # 开启官方 SDK 的流式请求
            response_stream = client.session.chat(
                session_id=session.id,
                message=prompt,
                stream=True
            )

            # 解析分块数据
            for chunk in response_stream:
                
                # 2. 执行期实时中断检查
                if interruption_queue and not interruption_queue.empty():
                    if status_reporter:
                        status_reporter("opencode_interrupted", {"message": "强制中断了 OpenCode 执行"})
                    return execution_trace + "\n[异常] Ciri 接收到强行中断信号，任务中止。"

                # 3. 数据流分流处理
                if chunk.type == "message":
                    if status_reporter:
                        status_reporter("opencode_thought", {"text": chunk.content})
                    execution_trace += f"🧠 思考/反馈: {chunk.content}\n"

                elif chunk.type == "tool_call":
                    if status_reporter:
                        # 截取过长的参数，防止前端 UI 崩溃
                        args_summary = str(chunk.arguments)[:100] + "..." if chunk.arguments else ""
                        status_reporter("opencode_action", {"action": f"调用 {chunk.tool_name} ({args_summary})"})
                    execution_trace += f"🛠️ 动作: [{chunk.tool_name}]\n"

                elif chunk.type == "error":
                    if status_reporter:
                        status_reporter("opencode_error", {"error": chunk.error})
                    execution_trace += f"❌ 底层报错: {chunk.error}\n"

            if status_reporter:
                status_reporter("opencode_finish", {"message": "OpenCode 任务执行完毕。"})
                
            # 任务结束后，清理底层 Session 释放资源
            # client.session.delete(session.id) 
            
            return execution_trace

        except Exception as e:
            err_msg = f"OpenCode 执行期间发生崩溃: {str(e)}"
            if status_reporter:
                status_reporter("opencode_error", {"error": err_msg})
            return execution_trace + f"\n❌ {err_msg}"

    # 显式重置函数名（防止闭包导致某些底层 Agent 框架反射获取 Tool Name 失败）
    opencode_delegate.__name__ = "opencode_delegate"

    return [opencode_delegate]

绝对的动态解耦： 这个工具本身没有引入任何全局变量，所有的状态（包括流式监听）都是被封装在每次 get_tools 调用周期里的，极其轻量安全。

契合 Swarm 架构： 你的 Ciri 正在往多智能体（Swarm）方向演进。opencode_delegate 就是一个标准的下级节点。Ciri（Leader）发号施令，OpenCode（Worker）在后台干活，并通过 status_reporter 绕过 Ciri 直接向前端汇报进度。

# OpenCode Sub-Agent Skill

This skill provides a delegation interface to the OpenCode underlying agent. It acts as an advanced "worker" node in a multi-agent swarm architecture.

Instead of performing atomic file operations, this skill takes high-level, complex engineering prompts and executes them autonomously within its own Agentic Loop (Think -> Act -> Observe -> Fix).

## Capabilities

- **Autonomous Multi-file Refactoring**: Write, modify, and refactor code across an entire project directory.
- **Terminal Execution**: Safely run shell commands (e.g., `npm install`, `pytest`, `cargo build`) to configure environments or test code.
- **Iterative Debugging**: Automatically read terminal error logs, analyze the root cause, and apply fixes without bothering the main agent.
- **Real-time Swarm Telemetry**: Streams its internal thoughts (`opencode_thought`), actions (`opencode_action`), and errors (`opencode_error`) back to the main UI via the side-channel status reporter.
- **Context Compression**: Returns a highly condensed "Execution Trace" report to the main agent, preventing context window bloat.

## When to use this skill vs `file_editor`

- **Use `file_editor` when**: You know exactly which lines to change in a specific file, or you just need to read a file's content to answer a user's question.
- **Use `opencode` when**: The user asks for a feature that requires creating multiple files, running tests, installing dependencies, or fixing a bug where you are not entirely sure of the root cause yet. Delegate the hard work!

# OpenCode 子智能体技能 (Sub-Agent Skill)

此技能提供了一个通向 OpenCode 底层智能体的委派（Delegation）接口。在一个多智能体（Swarm）架构中，它扮演着高级“执行者（Worker）”节点的角色。

与执行原子级的文件读写不同，此技能接收高层次、复杂的工程指令，并在其自身的智能体循环（思考 -> 行动 -> 观察 -> 修复）中自主执行，直到任务完成或彻底失败。

## 核心能力 (Capabilities)

- **自主多文件重构**: 在整个项目目录中自主跨文件编写、修改和重构代码。
- **终端命令执行**: 安全地运行 shell 命令（例如 `npm install`、`pytest`、`cargo build`）来配置环境、编译或测试代码。
- **迭代式 Debug**: 自动读取终端的报错日志，分析根本原因，并自动尝试修复，无需频繁打扰主智能体。
- **实时 Swarm 遥测**: 通过旁路状态报告器（status reporter），将其内部的思考 (`opencode_thought`)、动作 (`opencode_action`) 和错误 (`opencode_error`) 实时流式传输回前端 UI 界面。
- **上下文压缩**: 执行结束后，仅向主智能体返回高度浓缩的“执行轨迹 (Execution Trace)”报告，防止 Ciri 主模型的上下文窗口爆炸（Token Bloat）。

## 工具边界：何时使用此技能 vs `file_editor`？

- **优先使用 `file_editor` 的场景**: 当你确切知道要在哪个特定文件中修改哪几行代码时，或者你只需要读取某个文件的内容来回答用户问题。
- **必须使用 `opencode` 的场景**: 当用户要求开发一个新功能（需要创建多个文件、运行测试、安装依赖），或者需要修复一个你还不完全确定根本原因的复杂 Bug 时。请果断将这种耗时的试错任务委派给本工具！

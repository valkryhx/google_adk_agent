# OpenCode 技能显示与鲁棒性优化全记录

本文档详细记录了针对 `opencode` 技能在多智能体（Swarm）协作环境下的显示消失、数据持久化、路径对齐及并发安全等问题的迭代优化过程。

## 1. 核心问题背景
在初始版本中，`opencode` 技能存在以下几个痛点：
*   **内容消失**：任务执行时卡片有流式输出，但结束后内容会被简短的“执行完毕”替换。
*   **轨迹丢失**：刷新页面后，Worker 卡片内的执行细节（思考过程、bash 命令等）全部丢失。
*   **路径偏离**：当 OpenCode 后端启动目录与当前项目目录不一致时，生成的代码会“飞”到错误的位置。
*   **并发风险**：在尝试引入热加载逻辑时，存在不同用户/任务之间 Session 串台的隐患。

---

## 2. 优化历程

### 第一阶段：解决“执行完即消失” (UI 定格)
*   **现象**：`status_reporter` 发送 `finish` 事件时只携带了简短的 message，导致前端 UI 擦除了之前的流式轨迹。
*   **对策**：将 `accumulated_text`（流式轨迹）提升至**任务级闭包作用域 (Closure Scope)**。在任务结束时，主协程能从该闭包中提取完整的 **轨迹内容** + **最终总结** 并拼接成 `full_content`。
*   **结果**：卡片在变绿（完成状态）后，依然保留了之前的运行日志，且保证了不同并发任务间的 Session 隔离。

### 第二阶段：解决“刷新即丢失” (持久化)
*   **现象**：虽然 UI 实时显示了轨迹，但由于函数 `return` 值仅为摘要，框架持久化到数据库的内容过少，导致刷新后卡片缩水。
*   **对策**：彻底改变技能函数的返回策略。函数不再返回摘要，而是**直接返回全量执行轨迹**。
*   **结果**：实现了 UI 状态与存储状态的强一致性，刷新页面后执行轨迹依然稳固。

### 第三阶段：解决“幽灵代码” (路径对齐)
*   **现象**：OpenCode 默认在其服务端启动目录下操作，导致相对路径指令（如 `misc/test.py`）失效。
*   **对策**：在 `opencode_delegate` 中自动探测当前 Python 进程的绝对路径 (`os.getcwd()`)，并在 Prompt 头部强制注入 `[环境约束]`。
*   **结果**：强制 OpenCode 在当前工程根目录下执行所有文件读写和终端命令，解决了目录隔离问题。

### 第四阶段：解决“捕获不全” (事件流增强)
*   **现象**：由于 SDK 事件格式不统一，导致“思考过程”和“工具调用”经常漏掉，轨迹显得很空洞。
*   **对策**：
    *   引入 `get_attr_robust` 辅助函数，兼容对象属性与字典键值访问。
    *   扩展监听事件类型，涵盖 `thought`、`call.created`、`message.updated` 等。
    *   实现基于偏移量的增量截取算法，精准提取全量更新事件中的新增内容。
*   **结果**：Worker 卡片日志变得极其丰富且干练，实时呈现智能体的内心思考与每一步动作。

### 第五阶段：解决“并发安全” (架构回归)
*   **现象**：尝试热加载（`reload`）可能导致全局状态重置，在多任务并发时存在 Session 泄露风险。
*   **对策**：
    *   取消了 `get_tools` 里的强制 `reload` 逻辑，回归稳定架构。
    *   使用 `task_context` 闭包变量确保每个任务的轨迹相互独立。
    *   保留配置文件的动态读取，实现“配置级热加载”与“逻辑级强隔离”。

### 第六阶段：前端历史记录适配 (Swarm UI 呈现)
*   **现象**：虽然流式显示正常，但在查看历史对话记录时，OpenCode 的执行结果被当作普通的文本块处理，缺乏视觉层次感。
*   **对策**：修改 `src/adk_agent/static/script.js`，为 `opencode_delegate` 专门定制了历史卡片渲染逻辑。
    *   **Swarm 卡片模拟**：在历史记录中自动识别 `opencode_delegate` 的调用，并渲染为具有 `code_blocks` 图标的 `swarm-card`。
    *   **执行日志折叠**：引入了 `<details>` 和 `<summary>` 标签，将漫长的执行日志（Execution Logs）默认封装在可折叠的终端区域（`swarm-terminal`）内。
    *   **结果预览**：卡片头部实时显示任务 Prompt 的前 50 个字符作为预览。
*   **结果**：历史记录中的 OpenCode 执行过程既专业又整洁，不会因为日志过长而破坏页面的整体阅读感。

## 3. 核心技术补遗 (基于最新 Git Commit)

### 3.1 鲁棒性属性访问函数 (`get_attr_robust`)
为了应对不同底层模型（如九天、通义千问 3.5）以及不同版本的 Python SDK 对 SSE 事件属性封装的差异（有的以对象属性返回，有的以字典返回），引入了统一的属性访问层：
```python
def get_attr_robust(obj, attr, default=None):
    if obj is None: return default
    if hasattr(obj, attr): return getattr(obj, attr, default)
    if isinstance(obj, dict): return obj.get(attr, default)
    if hasattr(obj, "__dict__"): return obj.__dict__.get(attr, default)
    return default
```
这确保了 `session_id`、`delta`、`thought` 等核心字段的获取万无一失。

### 3.2 精准增量偏移量算法
由于部分 SSE 事件（如 `message.part.updated`）返回的是当前段落的全量文本，为了防止流式卡片中内容重复堆叠，我们维护了一个 `part_lengths` 状态字典：
*   **逻辑**：记录每个 `part_id` 已知文本的长度。
*   **操作**：仅截取 `current_val[old_len:]` 作为 `delta` 进行追加。
*   **效果**：保证了流式输出的文字是平滑递增的，没有任何回退或重复现象。

## 4. 优化后的代码特征 (tools.py)


1.  **纯函数工具集**：`get_attr_robust` 等工具函数提取至顶层，保证线程安全。
2.  **环境感知**：具备自动注入绝对路径的能力。
3.  **高信噪比日志**：过滤了无意义的重复，精准捕捉思考、动作与回复。
4.  **100% 隔离**：使用独立的 `session_id` 和任务闭包，支持高并发调用。

## 4. 结论
通过这一系列的优化，`opencode` 技能从一个简单的“命令执行器”进化为了一个**具备高度确定性、路径感知能力和完美可视化效果**的高级工程智能体。它在保持后端执行自治的同时，为前端提供了极致的透明度和可追溯性。

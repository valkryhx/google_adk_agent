## 9. 当前遗留问题
- 任务隔离维度仍以 `session_id` 为主，而非 `work_id`。
- 同一会话多次注册不同任务时，共享同目录与 `work.md`，存在串写/覆盖风险，影响“单任务可追踪性”。

## 10. 后续优化建议（仅建议，本次未实现）
1. 文档与产物按 `work_id` 分桶。
2. 在 `requirements/<session_id>/` 下建立 `works/<work_id>/` 目录，并将每个任务的 `work.md`、结果文件放入该目录。
3. 状态接口按 `work_id` 输出独立进度、执行轮次与完成态，前端支持按任务切换视图。
4. 当注册新任务时，避免复用旧任务 `work.md`；改为生成新 `work_id` 对应主文档并建立软链接/索引。
5. 增加任务停止条件的显式字段（例如 `should_stop=true`）与完成后自动降噪策略，减少完成后继续循环执行。
